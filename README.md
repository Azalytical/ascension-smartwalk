# SmartWalk · Успею вернуться

Команда **Ascension**, Build with AI Hackathon 2026, секция AI for Smart City.

[Открыть работающее демо](https://ascension-smartwalk.azamatbreach.workers.dev) · [Видеообзор на YouTube](https://youtu.be/EKrwOn43a5w) · [Исходный код](https://github.com/Azalytical/ascension-smartwalk)

Городской RAG-помощник для прогулок по Астане. Пользователь выбирает точку старта, доступное время и предпочтения. Система извлекает подходящие POI из автоматически собранной базы OpenStreetMap, проверяет время и формирует короткое объяснение по найденным данным.

Каждая карточка представляет **отдельный вариант** прогулки. Время включает дорогу туда, посещение, возвращение и запас 5 минут. Карточки не образуют один общий маршрут.

## Возможности

- Настоящий воспроизводимый сбор данных через Overpass. Исходные ответы и сведения о происхождении сохранены в `data/`.
- Поиск по географии, категориям и словарю русских, казахских и английских запросов. Кроме парков, кафе, музеев и достопримечательностей, подбираются рестораны и фастфуд, торговые центры, театры, кино и библиотеки. Запрос про дождь или холод оставляет только места под крышей.
- Проверка временного бюджета и максимальной продолжительности пути до генерации текста.
- Проверка режима работы из OSM на всё время визита: места, закрытые к приходу или закрывающиеся раньше конца визита, исключаются. Разбирается 145 из 146 форматов `opening_hours` в базе; неразобранный формат остаётся «неизвестно», а не угадывается.
- Объяснение с помощью Google Gemini (Gemini API; на демо `gemini-3.5-flash-lite`, у него 500 бесплатных запросов в сутки, по умолчанию в коде `gemini-3.8-flash`) по ограниченному контексту найденных POI. OpenAI Responses API остаётся запасным провайдером.
- Telegram-бот: геолокация кнопкой, затем запрос обычными словами, ответ теми же проверенными карточками.
- Источники у рекомендаций, явные неизвестные характеристики и экспорт плана в JSON.
- Карта Астаны, три демонстрационных сценария и адаптивный интерфейс.

## Локальный запуск

Требуется Node.js 22 или новее.

```sh
npm install
npm test
npm run dev
```

Открыть `http://localhost:8789`. Для генерации задать `GEMINI_API_KEY` (ключ из Google AI Studio) в окружении процесса. Не сохранять секрет в репозитории или браузерном коде. Необязательные переменные: `GEMINI_MODEL` (по умолчанию `gemini-3.8-flash`), `PORT` (по умолчанию `8789`). Если `GEMINI_API_KEY` не задан, но задан `OPENAI_API_KEY`, используется OpenAI (`OPENAI_MODEL`, по умолчанию `gemini-3.8-flash`). Имена переменных приведены в `.env.example`; загрузка этого файла автоматически не выполняется.

Без ключа или при недоступном провайдере поиск и расчёт работают, а интерфейс честно обозначает ответ без генерации. Такой режим не следует выдавать за выполненный вызов модели.

```sh
npm run build
```

Сборка создаёт единый Cloudflare Worker в `dist/server/index.js` и манифест Sites. Секрет провайдера задаётся отдельно в среде размещения.

## Cloudflare Workers (без биллинга Google Cloud)

```sh
npm run build
npx wrangler secret put GEMINI_API_KEY
npx wrangler deploy
```

Запросы к Gemini уходят с серверов Cloudflare, поэтому работают и там, где Gemini API недоступен из локальной сети. Генерацию ограничивает тот же учёт в памяти (`MEMORY_BUDGET` в `wrangler.jsonc`).

## Google Cloud Run

`Dockerfile` собирает тот же сервер без npm-зависимостей. В контейнере включён учёт запросов в памяти: до 8 в минуту с одного адреса и до 500 в сутки, поэтому сервис разворачивается одним экземпляром.

```sh
gcloud services enable run.googleapis.com cloudbuild.googleapis.com secretmanager.googleapis.com
printf '%s' "$GEMINI_API_KEY" | gcloud secrets create gemini-api-key --data-file=-
gcloud run deploy smartwalk --source . --region europe-west1 --allow-unauthenticated \
  --max-instances 1 --set-secrets GEMINI_API_KEY=gemini-api-key:latest
```

Сервисному аккаунту Cloud Run нужна роль `Secret Manager Secret Accessor` на этот секрет.

## Telegram-бот

Бот работает через вебхук `/telegram/webhook` того же сервиса и отвечает прямо в ответе на вебхук. Точка пользователя хранится в памяти только 30 минут и не передаётся модели.

1. Создать бота у @BotFather и придумать секрет вебхука (любая строка из букв и цифр).
2. Задать сервису `TELEGRAM_WEBHOOK_SECRET` (через `--set-secrets` или `--update-env-vars`).
3. Зарегистрировать вебхук: `TELEGRAM_BOT_TOKEN=... TELEGRAM_WEBHOOK_SECRET=... node scripts/telegram-setup.mjs https://<адрес сервиса>`.

## Друзья, встречи и события

Бэкенд `src/social/` работает в том же воркере: один SQLite Durable Object на город (`SocialHub`, доступен на бесплатном тарифе Workers), локально и в Docker — тот же код на `node:sqlite`. Отдельных ресурсов создавать не нужно: `npx wrangler deploy` применяет миграцию `social-v1` сам.

- **Профиль** без почты и телефона: имя и значок. В браузере хранится случайный токен, на сервере только его SHA-256.
- **Друзья** по ссылке-приглашению или QR (действует 3 дня). Блокировка сразу разрывает дружбу и скрывает точку.
- **Геопозиция только по согласию**: на 15 минут, 1 час или 8 часов, всем друзьям или выбранным, примерно (до ~150 м) или точно. Хранится одна последняя точка, истории перемещений нет; по истечении срока или по кнопке «Остановить» точка удаляется. Модели ИИ координаты не передаются.
- **Где встретиться**: сервер подбирает место из базы, до которого всем идти примерно одинаково (минимум самой долгой дороги, потом самый ровный расклад), и проверяет часы работы на время прихода.
- **Встречи** с друзьями: приглашение, ответы «иду / в пути / на месте», короткий чат, изменение и отмена с уведомлением.
- **События города**: публичные или только для друзей, лимит мест с листом ожидания, жалобы (после трёх событие скрывается), экспорт в календарь.
- **Второе устройство** (часы, планшет): шестизначный код на 10 минут.

API: `GET /api/social/state|events|event|invite`, `POST /api/social/<действие>` с `Authorization: Bearer <токен>`, `GET /api/social/places?q=` для поиска мест. Описание действий — `src/social/store.mjs`, проверки — `tests/social.test.mjs`.

## Как работает RAG

1. Скрипт импорта получает POI из OpenStreetMap через Overpass и нормализует их.
2. Детерминированный поиск извлекает релевантные записи по категории, тексту и расстоянию. Embeddings не используются.
3. Валидатор отбрасывает варианты, не помещающиеся во временной бюджет, и места, закрытые на время визита по режиму работы из OSM (`src/hours.mjs`).
4. Модель получает только извлечённые записи, запрос и оценки времени. Идентификаторы источников проверяются. Модель не меняет рассчитанное время.
5. Карточки показывают исходные факты и ограничения отдельно от сгенерированного объяснения.

## Ограничения и приватность

- Пешеходная навигация и поиск проходов не реализованы. Расстояние и время являются оценками: геодезическое расстояние, коэффициент обхода 1.35, скорость 4.2 км/ч. Ограждения, переходы, погода и индивидуальный темп могут изменить время.
- Часы работы — сведения из снимка OSM, а не подтверждение открытия сейчас. Тишина, свободные розетки, очереди, текущие события и безопасность не предполагаются.
- Указание «с ребёнком» меняет подходящие категории. Оно не подтверждает безопасность или оснащённость места.
- Приложение не ведёт историю координат и запросов. Точная координата старта не включается в контекст модели. Введённый пользователем текст и выбранные публичные POI передаются провайдеру генерации (для OpenAI с `store: false`); действуют также условия обработки данных провайдера. На бесплатном уровне Gemini API Google может использовать запросы для улучшения своих продуктов. Публичное демо сейчас работает на таком ключе, поэтому не пишите в запросе личные данные; для реального запуска нужен ключ проекта с подключённым биллингом.
- Карта и CDN требуют подключения к внешним сервисам. Вход в аккаунт не нужен.
- На размещённом демо (Cloudflare Workers) запросы к модели ограничены в памяти воркера: до 8 в минуту для одного сетевого адреса и до 500 в сутки. Координаты и текст запроса не сохраняются. При превышении лимита генерация отключается, а поиск по данным продолжает работать.
