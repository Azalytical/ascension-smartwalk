# Aidem: интеграции с Google и другими сервисами

Всё работает на бесплатных тарифах, без биллинга Google Cloud. Адрес демо: https://ascension-smartwalk.azamatbreach.workers.dev

| Что | Где | Сервис |
|---|---|---|
| ИИ-агент, который сам выбирает инструменты и показывает шаги | `/agent`, `POST /api/agent` | Gemini API, function calling |
| «Что это за здание?» по фото | `/agent`, `POST /api/vision` | Gemini API, мультимодальный ввод |
| Смысловой поиск, когда словарь не узнал запрос | `POST /api/recommend` | Gemini API, эмбеддинги `gemini-embedding-001` |
| Ответ голосом (русский, казахский, английский) | `/agent`, `POST /api/speak` | Gemini TTS |
| MCP-сервер с инструментами Aidem | `POST /mcp` | Model Context Protocol |
| Расширение Gemini CLI | `gemini-extension.json` | Gemini CLI |
| Агент на Google ADK | `integrations/adk/` | Agent Development Kit, готов к Agent Engine |
| Маршрут пешком, место на карте | `links.googleMapsWalk`, `links.googleMaps`, `links.twoGis` | Google Maps URLs, 2ГИС |
| Прогулка в календаре | `links.googleCalendar` | Google Calendar |
| Погода и закат | `GET /api/weather`, инструмент `get_weather` | Open-Meteo |

## Инструменты

Один набор инструментов (`src/tools.mjs`) используют и агент Gemini, и MCP-сервер. Все только читают данные.

- `plan_walk` — до 3 отдельных мест рядом, на которые хватит времени: туда, на месте, обратно и запас 5 минут; закрытые к приходу по часам из источника отсеяны. У каждого места «почему», план с часами, уверенность, предупреждения, источник и ссылки; плюс готовый мини-маршрут и ближайшее место за пределами лимита, если ничего не подошло.
- `search_places` — поиск по всей базе мест (OpenStreetMap и Overture Maps): название, слова, категория, близость к точке; статус по часам на сейчас.
- `place_details` — описание, адрес, телефон, сайт, кухня, Wi-Fi, доступность для коляски, часы и проверка на время визита.
- `build_route` — мини-маршрут из 2–3 мест: порядок с самой короткой ходьбой, минуты каждого отрезка, часы на момент прихода, помещается ли во время, ссылка на весь маршрут в Google Maps.
- `get_weather` — температура, как ощущается, ветер, осадки, закат и совет «лучше под крышу».

## Агент на Gemini (`/api/agent`)

`POST /api/agent {"query": "Час свободен, хочу кофе и пройтись", "lat": 51.1283, "lon": 71.4304, "minutes": 60, "withChild": false}`

1. Gemini получает запрос, время, «сейчас» по Астане и описания инструментов (function calling, режим `ANY`).
2. Модель сама решает, что вызвать: обычно погода, затем `plan_walk`, для «нескольких мест подряд» `build_route`. Не больше 6 вызовов инструментов и 5 обращений к модели.
3. Сервер выполняет инструменты и возвращает модели результат **без координат, ссылок и адресов источников**. Точку старта модель не видит: сервер сам подставляет её в инструменты.
4. Модель заканчивает вызовом `give_answer {summary, place_ids, route}`. Сервер проверяет, что все `place_ids` пришли из инструментов, а текст не содержит запрещённых утверждений («открыто сейчас», меню, цены и т. п.). Иначе ответ строится без модели из тех же инструментов (`mode: "fallback"`).
5. Ответ: `summary`, `places` (со ссылками Google Maps, 2ГИС, Google Календарь), `route`, `steps` (каждый шаг: инструмент, аргументы, что получилось, миллисекунды), `modelCalls`, `toolCalls`, `privacy`.

Модель: `GEMINI_AGENT_MODEL`, иначе `GEMINI_MODEL`, иначе `gemini-3.5-flash-lite`. Лимит: общий бюджет демо (8 запросов в минуту с адреса, 500 в сутки) и не больше `AGENT_DAILY_LIMIT` (150) запусков агента в сутки; сверх лимита отвечает подбор без модели.

## Смысловой поиск на эмбеддингах (`/api/recommend`)

Словарь ru/kk/en знает категории («кофе», «парк», «мұражай»), но не каждую фразу. Когда в запросе нет ни категории, ни вида места, ни намерения, которое их задаёт, сервер один раз вызывает `batchEmbedContents` (`src/semantic.mjs`):

1. Примеры запросов для каждой категории («подышать свежим воздухом» для парка, «выпить латте или капучино» для кафе, «қарным ашты» для еды) и общие запросы без категории («куда сходить рядом») превращаются в векторы один раз на воркер (`taskType: SEMANTIC_SIMILARITY`, 768 измерений).
2. Запрос сравнивается с ними косинусной близостью. Категория выбирается, только если она ближе общих запросов и заметно выделяется среди остальных; если две почти равны, берутся обе.
3. Подбор идёт по этим категориям с теми же фильтрами времени, часов и безопасности. В «Мы учли» появляется строка «Смысл запроса по эмбеддингам Gemini: парк», в ответе `retrieval.usesEmbeddings: true` и `retrieval.semantic` с моделью и тремя ближайшими категориями.

В модель уходит только текст запроса. Ошибка, таймаут (1,2 с, первый вызов воркера 3 с), неясный смысл или пустой результат оставляют ответ по словарю. Модель: `GEMINI_EMBEDDING_MODEL`, иначе `gemini-embedding-001`.

## «Что это за здание?» (`/api/vision`)

`POST /api/vision {"image": "data:image/jpeg;base64,...", "lat": 51.128, "lon": 71.43, "heading": 90}`

Сервер берёт до 12 мест в радиусе 900 м и сторону, где каждое находится относительно взгляда камеры (если есть компас). Gemini получает фото и этот список без координат человека и выбирает `placeId` только из списка или ничего. Название места берётся из базы (OpenStreetMap или Overture Maps), до 2 фактов помечаются как сгенерированные (`factsSource: "generated"`, в интерфейсе «идея ИИ»). При низкой уверенности факты не показываются. Фото не сохраняется. Страница уменьшает снимок до 768 px.

## Голос (`/api/speak`)

`POST /api/speak {"text": "..."}` → `{mimeType, sampleRate, data}`: 16-битный PCM в base64, браузер проигрывает его через Web Audio. Модель `GEMINI_TTS_MODEL` (по умолчанию `gemini-3.8-flash-lite-tts`), голос `GEMINI_TTS_VOICE` (по умолчанию `Kore`). Последние 12 фраз кэшируются в памяти воркера. Если озвучка недоступна, страница читает текст голосом браузера.

## MCP-сервер (`/mcp`)

Streamable HTTP без сессий, ответы JSON, протоколы 2024-11-05 … 2025-11-25. Методы: `initialize`, `ping`, `tools/list`, `tools/call` (результат и в `content`, и в `structuredContent`). Ошибки аргументов приходят как `isError: true` с понятным текстом. CORS открыт, лимит 60 запросов в минуту с адреса. Проверено официальным клиентом `@modelcontextprotocol/sdk`, Gemini CLI 0.64 (`gemini mcp list` → Connected) и Google ADK 2.12 (`McpToolset` видит все 5 инструментов).

**Gemini CLI**, одной командой:

```
gemini extensions install https://github.com/Azalytical/ascension-smartwalk
```

Или вручную в `~/.gemini/settings.json`:

```json
{ "mcpServers": { "aidem": { "httpUrl": "https://ascension-smartwalk.azamatbreach.workers.dev/mcp" } } }
```

Дальше просто спросить: «Я у Байтерека, есть час, хочу кофе и прогуляться».

**Claude Code:** `claude mcp add --transport http aidem https://ascension-smartwalk.azamatbreach.workers.dev/mcp`

**Google ADK:** см. `integrations/adk/README.md`.

## Ссылки в ответах

`/api/recommend`, `plan_walk` и агент добавляют к каждому месту `links`:

- `googleMapsWalk` — пешеходный маршрут в Google Maps **без точки старта**: приложение само начинает от места человека, Aidem его координаты в ссылку не пишет;
- `googleMaps` — точка на карте; `twoGis` — маршрут в 2ГИС (тоже без старта);
- `googleCalendar` — событие «Aidem: место» на время всей прогулки с описанием «туда / на месте / обратно / запас» и временем возвращения.

Ссылки — обычные адреса без ключей: ни Google, ни 2ГИС ничего не узнают, пока человек сам не нажмёт.

## Приватность

- Точка старта не уходит в Gemini ни в агенте, ни в распознавании фото, ни в эмбеддинги запроса. В Open-Meteo уходит точка, округлённая примерно до 5 км.
- На бесплатном уровне Gemini API Google может использовать запросы и фото для улучшения сервисов: поэтому на странице просьба не снимать людей и не писать личные данные.
- Сервер не хранит ни запросы, ни фото, ни аудио, кроме кэша последних 12 озвученных фраз в памяти.
